# Reconcile replay harness

Status: core harness and seeded generator implemented (40 golden cases, generated suites at three plan sizes, scoring, two baselines). Owns: the replay harness in `platform/contracts/src/planning/replay/`, its fixtures in `platform/contracts/test/replay/`, and the `Reconciler` interface.

The replay harness scores what happens after a message has been read into facts: does it change the plan, restate something already on it, raise a question, do nothing, or fail to resolve. It runs in memory with no database or network, inside the contracts unit run.

## The unit under test

`Reconciler = (input, { chooser }) => outcome`. The input is a plan (commitments, actions and projects with deadlines, contacts, remembered aliases, open asks) and one message with at most one fact. The outcome is one of five end states: `applied` (a create, update or cancel, with a target), `duplicate` (it restates a record), `asked` (held for a question), `no_effect` (with a reason) or `unresolved` (with a reason). It also carries up to five `candidates` (id, rank, score, lane), a `tie` flag, `usedChooser` and the chooser's pick. `replay-reference.ts` is today's behaviour behind that interface, including first-wins on equal matches; the real reconciler replaces it without touching the cases or the scoring.

A chooser sees a quote and at most five cards and answers `cN`, `none` or `unsure`. Every case runs on the deterministic path (a chooser that must not be called) and on three stub paths: `oracle`, `adversarial` and `noisy`. A real model never runs in CI.

## Cases and privacy

`golden.json` holds hand-written cases: an `id`, `tags`, the `input`, and a `gold` (end state, target, acceptable targets, op, reason, `mustNot`, `deny`). Names are fictional, addresses are `@example.test`, and the source is `message-test`. `lexicon.json` lists the only words a title, quote or name may use; the guard test fails on any other word, any other address, or secret-shaped text, so a pasted real message cannot merge. The guard is fail-closed: any other string field must look like an id, timestamp, address or enum value, so a new prose field is flagged until the guard is taught it, and a `note` is capped at 200 characters. A second set of tests runs it backwards, planting a real-looking title, quote, sender, display name, note, conversation key and reason into every committed case and requiring a finding. Add a word to the lexicon only for a neutral one.

A labelled set kept outside git (reviewed real cases) uses the same case format. `scripts/test/replay-case-files.mjs` reads a directory of `*.json` files (nothing when it is unset or missing; a directory inside a git checkout is refused) and `parseExternalCases` turns them into cases, so such a set needs no code change. Paths are resolved first, so a symlinked directory or file that points into a checkout is refused too. The committed suite does not depend on it.

## The seeded generator

`replay-generate.ts` builds a plan from a fixed fake vocabulary (words in `lexicon.json`, contacts at `example.test`) and derives each message from a plan record by one mutation, so the gold comes from the mutation and nothing is labelled. The 1x plan has about 411 records; 5x and 20x multiply the commitments, actions, projects and asks, not the contacts. The kinds are a restated or reworded event, a move, a cancellation (of a real, an unknown and a look-alike title), a new event, a past one, a message with no facts or no start time, a remembered alias, twin records, twins told apart by sender, a recurring neighbour, and for deadlines and asks the same, moved, new, numbered, twin and same-thread variants. The seed is fixed in the test (`DEFAULT_SEED`); plans and messages draw from separate streams, so asking for more cases never changes the plan or the cases before them. Each plan is built once, frozen and shared by its cases, so a runner copies only the message.

The CI run is 1,000 cases at 1x, 150 at 5x and 40 at 20x (about three seconds); cases are measured per kind, per tag and per size. `REPLAY_LARGE=1` runs about 18,600 cases and `REPLAY_SEED` changes the seed, both for a local sweep that checks the hard invariants and prints the figures (see the comment at the bottom of `replay-suite.test.ts`). On the chooser paths only the cases that ended `asked` are rerun, since no other case could have used a judge; a test holds that equal to running everything on the golden suite.

## Scoring and the baseline

Scores are overall, per tag and per plan size: a confusion matrix over end states, applied precision, false-merge, wrong-create and wrong-duplicate rates, Deny rate and Confirm accuracy, tie rate and tie resolution, recall at five, the share resolved without a chooser, questions per 100 messages and the unresolved share, each with a count pair that a Wilson interval can be drawn from.

`baseline.json` (golden) and `baseline-generated.json` (generated, with its seed and counts) are the last accepted results. The suite fails when applied precision, recall at five or the no-chooser share falls, and when any recorded figure differs, so a change of behaviour always shows in the baseline diff; a deliberate change updates the baseline in the same commit with the reason in the message. Two invariants are never ratcheted: nothing resolves to one target on a tied top rank without a chooser, and nothing does what a case's `mustNot` forbids. The baseline lists the cases that break them today (first-wins on ties, moved deadlines read as new); that list may only shrink. A third list, `adversarialNewWrongDuplicates`, holds the cases where an adversarial chooser pins a restatement to the wrong record; a weak judge can do that, so it is tracked rather than forbidden, and it too may only shrink. In the generated baseline the lists hold case ids, which carry the size and position.
